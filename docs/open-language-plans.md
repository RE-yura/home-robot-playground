# 開いた計画：どんな作業でも計画し、未学習の作業は VLA に試させる（2026-10-29）

ユーザーの指摘（2026-10-29）「計画自体はあらゆるタスクが出て良くない？実行が途中で失敗判定になればよいだけで」と、未学習の作業の扱いの選択「B：VLA に試させて時間切れ」に沿った変更。

## 何が変わったか

- **計画の形**：言語モデル（Qwen3-1.7B、ブラウザ内）は、作業の並び（1〜4 個）を出す。各作業は `{"skill": "mug" | "ball" | "other", "ja": 日本語の名前, "en": 英語の指示}`。
  - `mug`・`ball` は学習済みの作業。英語の指示は、モデルが何と書いても学習時の文（`Put the mug in the basket.`／`Put the tennis ball in the basket.`）に置き換える。
  - `other` は未学習の作業。モデルが書いた英語の指示をそのまま VLA に渡す。
  - 「対応範囲外」として計画を出さない扱いはなくした。指す物が分からない指示（「それを持ってきて」など）だけ聞き返す。
- **出力の決め方**：思考（最大 1024 トークン）のあとは、各位置で元のスコアが最大のトークンを選ぶ（貪欲）。思考が上限に達したら終了の印を入れて答えを書かせる。答えが形式に合わなければ、別の seed で最大 3 回までやり直す。以前の「6 通りの出力だけを許す」制約は、自由な作業名と両立しないためやめた。
- **VLA への英語の指示**：学習済みの 2 文は、書き出し時の区切り（トークン）をそのまま使う（数値は従来と同じ）。それ以外の文は、学習に使ったトークナイザ（SmolVLM2、チェックポイントの processor から取り出したもの、`public/models/vla-tokenizer/`、ハッシュ固定）でブラウザ内で区切る。トークナイザは、学習済みの 2 文の区切りを完全に再現できたときだけ使う（`src/learning/vla-instruction.ts`）。48 トークンを超える指示は切り詰めずに拒否する。
- **実行と判定**：学習済みの作業はこれまでどおりの判定（コップは壁の内側）。未学習の作業は成功の判定基準を持たず（`TaskEvaluator("none")`）、120 秒の時間切れ・転倒・台車ずれで失敗として終わる。計画はそこで止まる。進み具合の段階（接近・把持など）は学習済みの作業だけ表示する。
- **画面**：計画の各作業に「学習済み」「未学習」を表示し、未学習の作業には VLA に渡す英語の指示を示す。

## 段階の表示と、学習済みかどうかの判定（2026-10-29 追記）

ユーザーの質問「計画を段階にしてくれないのはなぜ？」への対応（選択 A：段階を書かせて表示だけ）。

- 学習済みの作業の 4 段階（映像から接近・把持・運搬と解放・かご内の静止確認）は画面側で決めた段階で、物理の実測で ✓ を付ける。言語モデルが作ったものではない。
- 未学習の作業は、言語モデルに段階（1〜5 行の日本語）を書かせ、「未確認」として並べる（✓ は付けない）。
- 計画の中で段階も書かせた版（03a6e66）は、8 指示中 4 つで作業の種類を取り違えたため、段階は計画のあとに別の短い問い合わせ（思考なし・貪欲）で聞く（acc9917）。
- さらに、作業の種類（mug / ball / other）も計画とは別に 1 作業ずつ短く聞き、その答えを優先する（4e54ed4）。計画の中だけで決めると、小さいモデルは「コップ」「ボール」と書いてあるだけで学習済みと付けがちだった（例を足した 7614d41 では 10 指示中 3 つで誤り）。学習時の英文をモデルが自分で書いた場合だけは、学習済みのままにする。
- 4e54ed4 の確認（手元、12 指示）：11 が意図どおり。初めて試した「ボールを床に落として」「コップを冷蔵庫の上に置いて」「かごを持ち上げて」は未学習、「マグカップをカゴへ入れておいて」「テニスボールをかごにしまって」は学習済み。誤りは「ボールを転がして」で、計画そのものが「ボールをかごに入れる」になった。2 回目以降の計画は、種類の判定と段階を含めて 3〜12 秒。
- 公開 URL（Workers version c19e1a8e、4e54ed4）で「コップをかごから出して。」「ボールを床に落として。」の段階表示を確認した。前の版の公開フォルダは `work/deploy-workers/site-389edea`。

## 見つかった不具合（2026-10-29）

- 公開 URL（4e54ed4）で「コップをかごに入れてから、かごから出して。」を実行すると、1 つ目の作業の成功の瞬間にまだ動いていた推論と、2 つ目の作業の最初の推論がぶつかり「Learned worker is busy」で止まった（ローカルの 389edea では偶然ぶつからなかった）。新しい連続実行の作業は、最初の撮影の前に前の推論の終わりを待つようにした（64999fa、物理は止めて待つ）。
- 縁の上で放したコップは「取り落とし」と数えられることがあり、計画の表示が「把持・持ち上げ」の ✓ を消していた。掴んで持ち上げたことを測った作業では、かごの中で静止したら ✓ を戻す（ccd13f7）。
- 修正後の公開 URL（Workers version 3e395f23）で同じ指示を最後まで実行し、コップは 27.2 秒で成功、2 つ目は 120 秒で時間切れ、表示も正しいことを録画で確認した。
